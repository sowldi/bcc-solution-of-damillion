# Оценка качества валидатора (Stage 10)

```powershell
.venv\Scripts\python -m evaluation.run_evaluation
.venv\Scripts\python -m evaluation.run_evaluation --quick          # без замеров 1000/2000
.venv\Scripts\python -m evaluation.run_evaluation --official ..\ai-requirements-validator-task-main\docs\requirements.md
```

Результат — `EVALUATION.md` (в корне) и `evaluation/results/results.json`. Сеть не нужна:
модель не вызывается, сбои API имитирует HTTP-заглушка на 127.0.0.1.

## Корпус

`evaluation/corpus/` — только собственные документы (библиотека, переговорные, доставка
цветов, фитнес-клуб). Рядом с каждым — `*.labels.json`:

- `expected` — внедрённые дефекты: якорь (ID документа или `quote:<фрагмент>`), правило,
  допустимые альтернативные правила (`alt`), второе требование для правил сравнения (`pair`);
- `traps` — ловушки: где перечисленные правила срабатывать не должны (число рядом с
  оценочным словом, отрицание, разные условия, разные параметры, «и далее» как
  последовательность действий и т. п.);
- `contradictions` — ожидаемый статус противоречия этапа 8;
- `semantic` — смысловые дефекты, которые правила по замыслу не ловят (учёт пропусков);
- `related_pairs` — пары об одном объекте (полнота отбора кандидатов);
- `verdict` — ожидаемый вердикт этапа 9.

`dev/` — для отладки; `test/` — held-out: разметка зафиксирована до первого прогона,
итоговые метрики — только по нему. Правила под корпус не подгонялись.

## Метрики

Только детерминированный слой (там разметка обоснована). Замечание верно, если совпадает с
меткой (правило, требование, пара); метка найдена, если её закрывает хотя бы одно замечание.
Важность info (CON-02) не считается. Precision/recall — по правилам, микро- и макро-
усреднение. Отдельно — ловушки, статусы противоречий, отбор кандидатов, вердикты, форматы
(MD/DOCX/PDF/TXT, сгенерированные из того же текста), стабильность (повтор,
`PYTHONHASHSEED`, обратный порядок пунктов), время и память, сбои API.

**LLM-слой не измеряется**: нужен реальный ключ или локальная модель и разрешение
владельца проекта. Чтобы измерить: добавить в `run_evaluation.py` вызов
`review_requirements`/`crosscheck_pairs` с настоящим провайдером на корпусе (не на
официальном документе без разрешения) и сравнить гипотезы с полем `semantic` разметки.

Официальный документ в корпус не входит; с `--official` в результаты попадают только сводные
числа.
